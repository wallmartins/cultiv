# Framework Agnostic Client SDK Core With Authenticated Transport

## Parent

- `docs/archive/prd/client-sdk-client-integration-surface.md`

## What to build

Redesign the SDK core so it becomes a framework-agnostic **Client Integration
Surface** with authenticated transport, typed errors, and no ownership of
signup/signin/session-establishment flows.

This slice should prove end-to-end that:

- the SDK core is independent from Next.js, React-specific adapters, and UI
  cache libraries
- platform-owned identity integrations can provide tokens to the SDK transport
  via `getToken` (sync or async)
- contract, HTTP, and transport failures surface through explicit typed errors
- the SDK exposes a dual API: Effect primary with a root `toPromise` helper
- every method accepts `signal?: AbortSignal` for cancellation
- differentiated retry policy: GET retries up to 3 times; POST/PATCH retries up
  to 2 times on safer status codes
- idempotency keys are auto-generated by the SDK for all mutating requests

## Acceptance criteria

- [ ] The SDK core exposes framework-agnostic product modules and transport primitives without UI-framework dependencies.
- [ ] The authenticated transport consumes tokens from injected platform identity integrations rather than owning auth-provider orchestration.
- [ ] Contract, HTTP, and transport failures are surfaced through typed client errors.
