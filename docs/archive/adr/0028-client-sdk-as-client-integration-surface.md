# ADR 0028: Client SDK as the Client Integration Surface

The `client-sdk` is the **Client Integration Surface** for web and mobile applications: it is the only frontend-owned layer allowed to consume the backend **Public API Surface**, it remains framework-agnostic, and it exposes product capabilities such as preview, executions, content types, voice, execution watch, and execution resume instead of raw route wrappers. We chose this because the product already has a backend-owned public surface and shared contracts, and the SDK should standardize authenticated consumption, transport resilience, and fail-fast contract enforcement without taking ownership of UI framework state, signup/signin flows, or direct backend route semantics. This ADR complements [ADR 0026](./0026-typescript-native-client-sdk-as-primary-consumer.md) and supersedes the auth ownership direction in [ADR 0005](./0005-auth-in-client-sdk.md): platform identity integrations own signup, signin, redirect, and session establishment, while the SDK is only an authenticated consumer that receives tokens for backend access. The product-facing SDK surface will center on `/me/*`, `/api/generation-preview`, and `/me/content-types`; legacy `/api/pipelines` and `/api/jobs` routes are not part of the product client contract, must not appear as first-class SDK capabilities, and should be removed from the public product surface as the backend cleanup proceeds.
